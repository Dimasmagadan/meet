## Architecture (13 findings)

**Strengths worth preserving:** atomic-write discipline everywhere (`writeAtomic`, PID+random tmp names, `linkSync` exclusive lock publication); rigorous lock ownership semantics (PID+token conditional release, exact-bytes stale reclamation); a consistent fail-open boundary around optional/biometric subsystems (each gates individually, catches at its own boundary, never touches `transcript.md`); pure-parser / injectable-sensor split (`parseLoadavg`, `parseWhisperJson`, `parseDiarizeOutput`, `parseCaptureLine`, `PressureSensor`, `GitRunner`, `isPidAlive`) making ~40 test files test real logic; A/B layering that shares `forEachAudibleChunk` so whisper-final and Parakeet see an identical chunk set; recovery-minded live path (`inFlightKey` double-transcription guard, `close()` quiesce before detached finalizer spawn, active lock cleared *before* the finalizer spawns so `gateWhileRecording` can't self-deadlock, unrecovered-audio detector preserving WAVs).

**[REMAINS]** 1. **`session.json` has no single owner — 13 write sites across 4 modules.** `writeSession()` exists in `storage.ts:141` but only `pipeline.ts:297,306` uses it; everyone else hand-rolls `writeAtomic(join(…,"session.json"), …)`: `cli.ts:393`; `recorder.ts:166,237,298,324,384,674`; `finalize.ts:70,918,965,979`. Worse, ownership is split by mutation, not by phase: `Recorder` and `Pipeline` hold the *same object reference* (`recorder.ts:62` → `pipeline.ts:55`) and both persist the whole object; `finalize.ts:727-729` then re-reads disk and cherry-picks `processedChunks` + `tags` only, silently dropping `lastError`/`autoStopReason`/`hasMeaningfulText`. Every new `Session` field is a fresh divergence risk. Direction: `Pipeline` as sole live-phase writer via a `SessionStore` owning the file plus a schema-level merge on phase handoff.

**[REMAINS]** 2. **`entries.jsonl` is documented as authoritative but is written only on the live path.** `appendEntryRecord` has exactly one call site (`pipeline.ts:284`); the final pass and `import.ts` write no records. Readers that treat it as truth need an escalating fallback pile: `filterStoredEntriesByAudio` re-analyzes WAVs (`finalize.ts:128-134`), `buildMicSegments` falls back to transcript-text presence (`mic-echo.ts:286-290`), and the "Me" talk-time row derives from live RMS records that don't exist for `'q'`-quit + final-pass meetings. Three representations of the same truth (in-memory `results`, `session.json.processedChunks`, `entries.jsonl`) merged by hand-tuned precedence in `buildBaseResults` (`finalize.ts:173-184`). Direction: make the final pass append records, or demote JSONL to an explicit live-only cache and name the finalize-phase authority.

**[FIXED — B11]** 3. **The markdown recovery round-trip loses mic source attribution.** `formatEntry` (`assembler.ts:44`) renders a mic entry relabeled by mic-diarization/mic-echo as `**[HH:MM:SS] Speaker N:**`; `parseTranscriptEntries` (`assembler.ts:94`) maps back with `label === "Me" ? "mic" : "sys"`. A relabeled mic chunk returns as `source: "sys"` on any recovery re-finalize, then gets diarized as a remote speaker — and `final-pass.ts:166-168`'s live-fallback lookup (`e.source === chunk.source`) can't find its own fallback text. Silent data corruption, not a display nit.

**[REMAINS]** 4. **`finalize.ts` is a 984-line orchestration god module** — live drain, final pass, echo filtering, sys diarization, registry matching, mic diarization, mic-echo attribution, talk-time, markdown rewrite, parakeet A/B, opencode index, unrecovered-WAV detection, session-dir cleanup, progress writing, two wait loops, plus direct reach into registry internals (`applySpeakerRegistry`, `finalize.ts:341-397`). Imports are even declared after function bodies (`finalize.ts:38-42`), a growth tell. Direction: an ordered `FinalizePlan` of steps (`DiarizeStep`, `MicEchoStep`, `TalkTimeStep`, `AbStep`…) each taking `(session, config, entries, ctx) => entries`, leaving `finalizeSession` a ~150-line sequencer.

**[PARTIAL — `expandPath` moved to a cycle-free leaf (`paths.ts`); `DEFAULT_*_PATH` constants still live in the feature modules]** 5. **Type-level dependency cycle `storage ↔ types ↔ git-context`.** `types.ts:1-4` imports `triggers`/`phrasebook`/`vocabulary`/`git-context`; `git-context.ts:5` imports `storage`; `storage.ts:8-9` imports `locks`/`recording-state`, which import `types`. All cross edges into `types` are `import type` (erased), so runtime-benign — but the foundational module now transitively depends on four feature modules for default-path constants. Direction: move `DEFAULT_*_PATH` constants into a leaf module or `types.ts`.

**[PARTIAL — `spawnBackgroundFinalizer` and `checkFfmpeg`/`ffmpegAvailable` consolidated into `storage.ts`; `selectModel`, `runWhisper`, and the `mode: "full"`/`chunkDurationSeconds: 15` Session stub remain]** 6. **The import path is a parallel transcription pipeline, not a consumer of the shared one.** Duplicated: two identically-named `spawnBackgroundFinalizer` (`cli.ts:746` vs `recorder.ts:427`, identical spawn differing only in logging); two model-resolution strategies (`storage.resolveWhisperBin`/`resolveModelPath` vs `import.selectModel`); `checkFfmpeg` duplicating the `WHISPER_CANDIDATES` pattern; `runWhisper` re-implementing exec+parse+cleanText+phrasebook. The `Session` it writes is a stub (`mode: "full"`, hardcoded `chunkDurationSeconds: 15` at `import.ts:175` vs the 30 s live default) and emits no `entries.jsonl`/`speakers.json`/talk-time — so `meet transcribe` output can never feed `meet speakers suggest`, `meet rename`, or dashboard talk-time. Direction: a shared `transcribeWavFile(wav, {pass, format})` primitive and a real `mode: "file"` session identity.

**[REMAINS]** 7. **Every WAV is read and metered twice on both paths.** `transcribeChunk` computes RMS/peak internally (`transcriber.ts:149-153`) after its callers already did (`pipeline.ts:224` then `:239`; `final-pass.ts:67` then `:150`) — and the final pass discards the returned metrics. Metering is owned by the wrong layer and costs a full file read + PCM scan per chunk on the hot path.

**[FIXED]** 8. **Per-chunk config reload re-does all work.** `loadConfig` runs per chunk (`pipeline.ts:221`) and per sys-text chunk (`attention.ts:42,46`); each call does `readFileSync` + `JSON.parse` + `sanitizeFileConfig`, and `isValidConfigValue` (`storage.ts:76-96`) constructs three `new Set([...])` literals *inside* the function — ~79 keys × 3 set constructions per call. `lastValidFileConfig` (`storage.ts:45`) caches validated values, not the parse. Direction: hoist the Sets to module scope and add an mtime guard (`statSync` compare) that skips parse+sanitize when unchanged — the pattern `phrasebook`/`vocabulary`/`triggers` already use.

**[FIXED]** 9. **Three overlapping gating policies + an overloaded `status: "paused"`.** `waitForInactiveRecording` (`finalize.ts:186-202`, whole-pass, unbounded, used only with `pauseForActiveRecording`); `throttleHold`'s recording hold (`system-monitor.ts:303-310`, per-chunk, unbounded by design); `whenNotOverloaded` (`system-monitor.ts:227`) — the superseded primitive, still used by `diarization-ab.ts`, which therefore **skips `gateWhileRecording`** unlike every other batch pass. `"paused"` means both "user pressed pause" and "finalizer waiting for a slot" (`recording-state.ts:18-22`). Direction: one `Gate` abstraction with declared policies, and a distinct wait state/field so status classification doesn't need heuristics.

**[FIXED]** 10. **The global final-pass lock is double-duty as the registry mutex.** `acquireGlobalFinalPassLock("<registry-mutation>")` at `speaker-rename.ts:138`, `cli.ts:910` (forget), `cli.ts:1003` (enroll-self) — held for the *entire* final pass (`finalize.ts:791` → released `:911-913`), i.e. through the multi-minute retranscription. `meet rename` on meeting A is blocked for the whole duration of unrelated meeting B's final pass. Safe (the re-entrancy at `locks.ts:237-239` is correct) but the locked resources — a CPU/Metal slot vs a JSON biometric store — are unrelated. Direction: a separate `registry.lock`.

**[REMAINS]** 11. **Fail-open swallowing is uneven in finalize.** The `warn`-once pattern is used well in the live path, but the finalize phase silently drops `speakers.json` (`finalize.ts:888` — the input to `meet rename`/`meet speakers suggest`), progress writes (`:70,979`), `matches.log` (`:371`), `diarization-ab-report.json` (`:607`), and `copyLiveTranscript` (`:736`), while `mic-echo.ts` and `runDiarizationAbStep` *do* warn on analogous failures. A disk-full during finalize produces a meeting that looks complete but is missing its speaker record, with no signal anywhere. Direction: one `writeArtifact(path, data, {required|advisory})` helper feeding the already-collected `warnings[]`.

**[REMAINS]** 12. **`Recorder` aggregates ~12 responsibilities** (853 lines, 20+ private handler fields): capture lifecycle, SIGINT/TERM/USR1/USR2/WINCH, raw stdin + Cyrillic-layout hotkeys (`recorder.ts:766-778`), 5 s status tick, tag picker, `retitle`/`ask` marker IPC, auto-stop, pause accounting, summary wiring, opencode guard. The status tick (`:586-638`) is effectively an event loop doing tag/retitle/ask/auto-stop as side effects. Direction: extract `MarkerQueue`, `AutoStopPolicy`, `HotkeyRouter`.

**[FIXED]** 13. **Long-tail duplication.** `expandPath` ×5 (`storage.ts:27`, `phrasebook.ts:115`, `triggers.ts:101`, `vocabulary.ts:103`, inlined at `vad.ts:19-21`); `speakerSortKey` ×2 (`talk-time.ts:30`, `speaker-rename.ts:34`); `formatEntry`/`formatSummaryEntry` drift (see slop #2); `AMBIGUITY_MARGIN` duplicated (`speaker-registry.ts:29` exported vs `mic-echo.ts:38` local) and `NEAR_ANCHOR_PORCH` (`live-speakers.ts:34`) == `CENTROID_ATTACH_PORCH` (`speaker-registry.ts:25`) == 0.65, same concept, three names; `AudioMetrics` interface declared in both `types.ts:204` and `audio-metrics.ts:3`; `transcriber.ts:79` re-exports audio-metrics functions nothing imports from there.

## Bugs

### P1 — data loss

**[FIXED]** **B1. The finalize safety net reverts the entire final pass on ordinary meetings.** `src/filters.ts:141,154`, `src/finalize.ts:830-836`. Two of the four mic-drop sites in `filterEntries` — `isDuplicate` (same-index sys text) and `isAcknowledgement` (≤3-token backchannel) — drop via bare `continue` without pushing to `droppedEcho`. The net compares final-pass entry count against `effectiveBaseEntries` (which excludes only *recorded* drops), sees fewer entries, and executes `entries = baseEntries` — discarding the entire turbo transcript and re-admitting the echo. Fires on any no-headset meeting with backchannels ("ага", "понятно"), not pathological ones. **Reproduced by two independent review passes against current source.** Compounded: the fallback restores `baseEntries` rather than `effectiveBaseEntries`, undoing even the recorded drops. Fix: push duplicate/ack drops into `droppedEcho` (the finalize comment at :774-777 already declares them the same class), and assign `effectiveBaseEntries` on the fallback path; consider making the net per-chunk instead of wholesale.

**[FIXED]** **B2. `--no-text-timeout` is a dead flag (commander negation trap) — and the underlying auto-stop cannot fire when it's needed most.** `src/cli.ts:47,53,419`, `src/recorder.ts:559-560`. Commander 12 sets `negate=true` for any long flag starting `--no-` and strips the prefix, so `--no-text-timeout 5` stores its value under `textTimeout` and `opts.noTextTimeout` never exists. **Reproduced with the installed commander:** `parse(["--no-text-timeout","5"])` → `{textTimeout: 5}`. The auto-stop therefore always uses `config.noTextTimeoutMinutes`; the documented flag is dead. *(One review pass traced the option→handler wiring and believed the flag live; direct verification of the produced key name shows it is not.)* Second, independent defect in the same feature: the auto-stop guard requires `hasMeaningfulText === true`, so a recording whose mic never produced text — exactly the failure the timeout exists for — sits forever, status line showing `no text: waiting`. Fix: rename the flag (or read the negated key) **and** drop the `hasMeaningfulText` precondition; add `cli.test.ts` — its absence is why this shipped.

**[FIXED]** **B3. [Swift] `AVAudioEngine` is mutated from two threads.** `MicCapture.swift:101-145,282-301`. `.AVAudioEngineConfigurationChange` is registered with `queue: nil`, so `handleEngineConfigurationChange` → `restartCapture` runs on the engine's *background* queue calling `removeTap`/`engine.stop()`/`installTap`/`engine.start()`, while `CaptureRunner.run()`'s 1 s loop calls `recoverIfStalled()` and Ctrl-C calls `stop()` on the **main** thread. The only mutual exclusion is the bare `isRestarting` flag — a non-atomic cross-thread read; AVAudioEngine is documented as not thread-safe. **Trigger: any audio-hardware reconfiguration mid-meeting** (Bluetooth headset connect/disconnect, headphone plug, sample-rate switch — these fire in bursts). Impact: double `installTap`, tap torn down mid-flush, corrupted engine graph → silent stall or exception while recording. The 5 s restart cooldown and 3 s stall monitor self-heal *most* collisions, but the state torn in between is a lost/garbled segment. Fix: route all control-state mutation and engine access through one serial control queue (the pattern already used for `writerQueue`), or make `MicCapture` an `actor` (the CLI targets macOS 14.0+).

### P2 — correctness

**[FIXED]** **B4. Talk-time undercount on essentially every default-quit session.** `pipeline.ts:126-135,182-189`; `recorder.ts:437-462`; `finalize.ts:709-715`; `final-pass.ts:229-238`; `talk-time.ts:20-28,43-46`. The default quit paths (`q`/Ctrl-C/SIGINT/SIGTERM/both auto-stops) call `shutdown()` → `pipeline.close()`, which closes the watcher but does **not** drain the queue — unlike `stopAndFinalizeForeground` (`recorder.ts:489`, which calls `pipeline.stop()`). The background finalizer then hits `finalize.ts:715` and calls `close()` again (not `stop()`) whenever the final pass will run (`finalRetranscribe: true`, the default), so those chunks are never live-transcribed in *either* process. The final pass recovers the *text* into transcript.md but `runFinalPass` builds entries purely in memory — no `appendEntryRecord` anywhere in the file — and `computeTalkTime`'s `activeChunkSeconds` counts only entries.jsonl records, so every undrained 30 s chunk contributes zero talk time. The "Me" row falls back to this count whenever `micWasDiarized` is false (headphones, no bleed, embed failure); "Others" uses it whenever diarization is off/failed. Trigger: quit while the status line shows any live-queue lag. Fix: drain live chunks in the finalizer before the final pass, have the final pass write entry records for chunks lacking them, or derive the fallback from the WAV set + transcript text (as `mic-echo.ts:233-240` already does for its corner case).

**[FIXED]** **B5. Echo-dropped mic chunks double-count the remote speaker's talk time.** `mic-echo.ts:210-219,275-294`; `finalize.ts:862-872`; `talk-time.ts:48-53`. `buildMicSegments` receives the full `attributed` map and emits a talk-time span for every attributed index — including chunks dropped as echo-covered. Those spans merge with the sys diarization segments and `computeTalkTime` sums per-speaker durations across **both** timelines, so the same speech is counted once on the sys side and once on the mic side under the same canonical "Speaker N". Trigger: speakerphone/no-headset call with `micEchoAttribution: true` (default). Fix: pass `drops` into `buildMicSegments` and skip dropped indices.

**[FIXED]** **B6. The P1 text-coverage echo gate is unreachable when the same-index sys chunk is empty.** `filters.ts:127-155`. The coverage check builds a `{N-1, N, N+1}` sys token neighbourhood, but the whole block runs only when `sys[N]` itself has text (`if (sys && sys.text)` at :140 gating `isDuplicate`, the coverage check, and `isAcknowledgement`). When a mic echo's sys counterpart lands in an adjacent chunk (chunk boundaries are not utterance-aligned), the gate is skipped and the mic entry keeps the wrong "Me" label. `mic-echo.ts:99-107` (`hasSysCounterpart`) runs the coverage check regardless of same-index text, confirming the intent. The P2 audio gate (`:135-138`) still applies, so this is partial-coverage, not total. Fix: restructure so the neighbourhood check runs whenever *any* of {N-1,N,N+1} has sys text; keep `isDuplicate(mic, sys[N])` gated on same-index text.

**[FIXED]** **B7. `writerErrorCount` is a lifetime budget, not a consecutive-failure budget.** `MicCapture.swift:31,211-229`; `SystemAudioCapture.swift:38,176-195`. The counter increments on each failed write and is never reset after a *successful* `abortCurrentChunk` + `startChunk()` recovery, so four isolated blips anywhere in a long meeting (iCloud/Time Machine contention, a momentarily full disk, a sluggish external volume) permanently halt the stream even though every reopen succeeded. Compounding: `finalizeChunk`'s `destinationExists` path (`WAVWriter.swift:99-104`) throws once per pre-existing chunk and lands in this same counter — a recovery in a session dir that already has N chunks burns N attempts. Fix: reset `writerErrorCount = 0` after a successful `startChunk()`.

**[FIXED]** **B8. Calendar auto-start resolves the winning occurrence before the start attempt.** `CalendarAutoStartController.swift:207-212`. Every ranked candidate (winner included) is inserted into `resolvedOccurrences` before `startIfPermitted`; if the spawn fails (`meet` not resolvable on the augmented PATH, `node` missing, `proc.run()` throwing) that occurrence stays resolved and is never retried for the rest of the meeting. `recordingController.start()` returns `Void` (`RecordingController.swift:40-85`), so the controller cannot distinguish launched from failed. Fix: insert the losers eagerly, resolve the winner only after the process actually launched (make `start()` return `Bool`/throw).

**[FIXED]** **B9. `attachToExistingSession` trusts the lock PID without verifying the process.** `RecordingController.swift:225-243`, `SessionMonitor.swift:20-24`, `isPidAlive` at `:265-267`. If a recording dies leaving a stale lock and macOS later reuses that PID (`kern.pid_max` wraparound on a busy machine), the menu bar attaches to an unrelated process and a subsequent Pause/Stop/Extend delivers SIGUSR1/SIGINT/SIGWINCH to an arbitrary app — potential data loss in *that* app. Fix: verify process identity at attach time (command path matches `node`/`meet`), re-verify immediately before signalling, treat mismatch as stale.

**[FIXED]** **B10. MicCapture's interleaved-PCM branch misreads the buffer.** `MicCapture.swift:169-185`. For an interleaved multi-channel format, `floatChannelData[0]` is the flat interleaved stream, so `floatData[0][i]` returns channel `(i % channels)` of frame `(i / channels)` and only `frameLength` floats are read — 1/channels of the audio. The guard routes interleaved into `ch = 0`, i.e. precisely into this bug. Today's VoiceProcessing output is non-interleaved (the 9-channel case is handled correctly by `findLoudestChannel`), so the branch is dead code — but if any device ever reports interleaved, the capture silently produces garbage with zero error. The `int16ChannelData` fallback (`:181-184`) has the same shape. Fix: read `floatData[0][i * hwChannels]` in the interleaved case.

**[FIXED]** **B11. Markdown fallback recovery misattributes mic "Speaker N" entries and can drop them.** `assembler.ts:94` (see architecture #3), producers at `live-speakers.ts:164-180` and `finalize.ts:498-511`, impact path `finalize.ts:749-760` → `:117-142`. On the crash-recovery path (entries.jsonl missing a chunk), a mic "Speaker N" line parses as `sys-NNN`; since no `sys-NNN.wav` exists in mic mode, `filterStoredEntriesByAudio` scores it `-Infinity` and drops it — the text is lost from the final transcript.
