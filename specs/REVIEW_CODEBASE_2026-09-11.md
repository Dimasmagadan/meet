**Project review — 2026-09-11**

Reviewed working tree at commit `4426301` plus the uncommitted mic-echo attribution feature (`src/mic-echo.ts` and wiring) built in the same session. Focus: recording lifecycle, finalization/echo pipeline, CLI/import surface, native audio writer/restart behavior, menu-bar/calendar orchestration, tests, and the AGENTS.md docs-sync contract. The 2026-08-21 and 2026-09-05 reviews were used as leads and their findings re-checked against current source; repaired items are not carried forward. Application code was not changed as part of the review — with one exception: the review itself caught a defect in the new `mic-echo.ts` talk-time segment builder (missing JSONL record treated as silence), which was fixed and tested before this document was written, so it is not listed below.

14 findings: two P1/high, twelve P2/medium (one of them a cluster of small CLI defects), plus a lower-priority Swift note list and a docs/tests section. "Reproduced" means an isolated probe exercised the relevant production code or dependency; "static" means the finding follows from the inspected control flow.

1. **[P1] Record every echo-filter drop class in `droppedEchoKeys` — the finalize safety net currently reverts the whole final pass.** `src/filters.ts:141,154`, `src/finalize.ts:829-835`: the safety net compares final-pass entry count against `baseEntries` minus `droppedEchoKeys`, but two of the four mic-drop sites in `filterEntries` — `isDuplicate` (same-index sys text) and `isAcknowledgement` (any ≤3-token mic backchannel) — drop without pushing to `droppedEcho`. **Reproduced against the compiled production `filterEntries`:** a mic chunk duplicating sys text and a mic "ага понятно" were both dropped while `droppedEchoKeys` stayed empty, so the net sees fewer entries than the unfiltered live set and executes `entries = baseEntries` — discarding the entire medium-model transcript and re-admitting exactly the echo text the filters had removed. This fires on ordinary no-headset meetings (backchannels are common), not pathological ones; the revert also restores `baseEntries` rather than `effectiveBaseEntries`, undoing even the recorded drops. Fix: push duplicate/ack drops into `droppedEcho` (the finalize comment at :774-777 already declares them the same "supposed to shrink the count" class), and/or make the net per-chunk instead of wholesale.

2. **[P1] `--no-text-timeout` is silently ignored (commander `--no-` negation trap).** `src/cli.ts:46,52,378`: commander 12 sets `negate=true` for any long flag starting `--no-` and strips the prefix, so the flag stores its value under `textTimeout` (as a boolean), and `opts.noTextTimeout` never exists. **Reproduced with the installed commander:** `parse(["--no-text-timeout","5"])` → `{textTimeout:true}`. The auto-stop no-text timeout therefore always uses `config.noTextTimeoutMinutes` and the documented flag is dead. (`--no-summary` only works because the code happens to read the negated name.) Fix: rename the flag or read the negated key commander actually produces; add a CLI parse test — `src/cli.ts` currently has none, which is how this survived.

3. **[P2] `meet status` shows a live paused recording under "Queued / stalled" with `meet finalize` recovery advice.** `src/status.ts:26-31`: the `paused` status is overloaded (user-pause vs finalization-wait) and the bucket filters never consult `classifyRecordingSessions`' lock/capture-liveness classification. A user-paused session with a live controller appears both under "Recording:" and as `paused (no finalizer)` with advice to run `meet finalize` — which blocks on the held active lock and, after resume, races the recorder on `session.json`/`entries.jsonl` and deletes the session dir under it. Same collision for a dead-controller paused session whose capture is alive (shown both as orphan and as queued). **Static.** Fix: route the queued/finalizer buckets through the existing classification.

4. **[P2] A controller death inside the stop window makes a live capture unclassifiable as orphan.** `src/recorder.ts:235-246` persists `status: "stopped"` *before* `stopCapture()` (up to ~5 s: SIGINT → flush → SIGKILL fallback) and before `clearActiveRecordingLock()`; `src/recording-state.ts:27-29` gates the orphan branch on `status` recording/paused only. A SIGKILL in that window leaves `stopped` + live `capturePid` + stale lock: the next `meet start` prints a warning and proceeds (two concurrent captures), `meet status` files it under "Stopped" with finalize advice, and `meet finalize` deletes the session dir while the orphaned capture still appends chunks. **Static.** Fix: treat recently-stopped sessions with a live `capturePid` as orphans, or persist a `stopping` state before terminating capture.

5. **[P2] `startCapture` error handling fails in both directions.** `src/recorder.ts:159-212`: (a) no `'error'` listener on the spawned capture — async spawn failures (EACCES, binary removed after `checkSetup`) crash with an unhandled `'error'` event instead of reaching the intended catch (which is otherwise dead code; Node probe confirmed the emit-then-uncaught semantics); (b) the post-spawn `writeAtomic(session.json)`/lock writes are inside the same try — if they throw (disk-full), the catch clears the lock and `exit(1)`s *without killing the already-running capture*, and since the failed write was the one persisting `capturePid`, the orphan is invisible to `classifyRecordingSessions`. **Static + Node-semantics probe.** Fix: attach an `'error'` handler; kill the child in the catch before exiting.

6. **[P2] Stale-lock reclaim unlinks by path without revalidating at unlink time — two processes can both own the same lock.** `src/locks.ts:98-114,134-155`: readers observe a dead pid, then `unlinkSync` unconditionally; `cleanStaleLock`'s byte-compare and its unlink are two separate steps, so with a pre-existing stale lock (every controller crash leaves one) plus two concurrent actors, B unlinks A's freshly published lock and acquires its own — both record; the same window lets two finalizers own `finalizer.lock`/the global final-pass lock and rewrite the same session. Window is microseconds wide but the code nowhere enforces what its comment claims. **Static.** Fix: unlink the observed inode (open+fstat compare, or `link()`+`unlink()` dance), not the path.

7. **[P2] Markdown fallback misclassifies labeled mic entries as `sys`, and markdown beats JSONL in the recovery merge.** `src/assembler.ts:94-104` infers source from the label (`label === "Me" ? mic : sys`), so a mic entry carrying a diarized/registry label re-parses as `sys-NNN`; `buildBaseResults` (`src/finalize.ts:744-759`) merges with markdown-over-JSONL precedence — the opposite of what its own comment claims — so re-finalizing a crashed session whose transcript contains such lines replaces the real sys utterance with the mic copy (duplicated content, authoritative JSONL text silently overridden). **Static.** Fix: keep JSONL precedence (fix the merge order or the comment), and/or stop inferring source from labels.

8. **[P2] Concat offsets trust the WAV header's claimed data size.** `src/diarization.ts:107-127`: `copyWavData` returns the header's `dataSize` even when the file is truncated (writer killed mid-chunk — precisely the crashed-session recovery that re-finalizes), shifting that chunk's offsets and every later chunk's `cursorSeconds`; diarization then segments the actual (shorter) audio and all overlap math attributes speech to wrong chunks for the rest of the meeting. `readPcmSamples` already clamps to real file length; `copyWavData` should count bytes actually piped. **Static.**

9. **[P2] CLI defect cluster (all static, each small):** `meet tag`/`meet tags --session` skip `expandPath` so a quoted `~/...` path writes tags state into a literal `~` directory under cwd (`src/cli.ts:101,116`); `meet retitle`/`meet ask` compare expanded-but-relative paths against the absolute `lock.sessionDir` and always report "No active recording" (`src/cli.ts:754-757,785-788`); `--background` finalization failures are invisible (detached spawn, `stdio: "ignore"`, no validation — `src/cli.ts:705-714`); `spawn` without an `'error'` listener in `runDoctor`/`enroll-self`/the background finalizer crashes uncaught on exec failure (`src/cli.ts:621-628,920-921,707-711`); `process.exit(1)` inside `try` skips `finally`, leaking `/tmp/meet-enroll-self-*` dirs containing raw mic WAV audio and exiting `speakers forget` while still holding the global final-pass lock (`src/cli.ts:934-958,878`); import treats "no speech detected" as batch success and leaves an empty meeting dir, and `runWhisper` masks a whisper zero-output run as success (`src/import.ts:160-163,287-299,94-98`); `speaker-rename` rewrites content before persisting `speakerNames` (a retry with a different name re-targets the stale canonical label) and its reverse-resolution can shadow a canonical id after a name collision (`src/speaker-rename.ts:83-126`); `meet dashboard --output` into a missing directory crashes with a raw stack (`src/dashboard.ts:406-407`).

10. **[P2] Writer-error budget is per-process, not per-episode — four transient storage errors over a long meeting permanently halt a healthy stream.** `native/AudioCapture/Sources/AudioCapture/MicCapture.swift:210-229`, `SystemAudioCapture.swift:175-193`: `writerErrorCount` increments on each failed write but is never reset after a successful recovery, so the fourth isolated hiccup (each individually recovered and logged) triggers the permanent halt — mic dies for the rest of a full-mode meeting, mic-mode capture exits entirely. **Static.** Fix: reset the counter after a successful recovery open.

11. **[P2] Full mode becomes a silent no-output zombie when the mic storage-halts and no `SystemAudioCapture` object exists.** `native/AudioCapture/Sources/AudioCapture/main.swift:144,157`: `systemCapture` stays nil on macOS 14.0/14.1 or after an `--allow-degraded` sys-start failure, so neither zombie-break condition fires when the mic later halts — the process runs to the duration cap recording nothing while the menu bar shows a live session. **Static.** Fix: exit when no stream is alive and producing, independent of `mode`/`sys != nil`.

12. **[P2] An initial `startTap` failure leaks the process tap + aggregate device for the session's lifetime in `--allow-degraded` full mode.** `native/AudioCapture/Sources/AudioCapture/SystemAudioCapture.swift:66-135`: `tapID` is committed before six subsequent throwing points with no teardown on this path, and CaptureRunner only assigns `systemCapture` on success, so `stopAll()` can never reach the half-built objects; the restart path is correctly covered. **Static.** Fix: defer-on-error teardown in `startTap` (or a partial-startup cleanup in the runner's catch).

13. **[P2] Menu-bar pause/resume are fire-and-forget signals the recorder silently drops while opencode is busy — UI/capture desync with a privacy failure mode.** `native/MenuBar/Sources/MeetMenuBar/RecordingController.swift:87-97` sets `.paused`/`.recording` immediately after `kill(pid, SIGUSR1/2)`; `src/recorder.ts:654,744-748` drops the toggle while `opencodeBusy()` (up to ~60 s, opened by the notch Ask-AI flow, invisible in headless mode). Result: the menu shows "Paused" while audio keeps recording, or shows "Recording" while the meeting is actually paused. **Static.** Fix: reconcile the menu state against the recorder's authoritative persisted status instead of assuming.

14. **[P2] `isPidAlive` has no process-identity check, so PID reuse pins a stale lock indefinitely** — "Another recording is already active" until the recycled pid happens to exit. `src/locks.ts:17-24`; lock records carry `startedAt` that no reader compares. **Static, low likelihood.** Fix: compare the recorded start time (or `ps -o lstart`) before trusting liveness.

**Lower-priority Swift notes (real, narrow preconditions):** `MicCapture`/`SystemAudioCapture` control state (`isRunning`/`isRestarting`/`lastRestartTime`, teardown) is touched from multiple threads without synchronization — a stall-restart racing a config-change restart can double-stop/start the engine or double-destroy tap/IOProc (MicCapture.swift:10-11,19,119-125; SystemAudioCapture.swift:270-288); with `--silence` enabled, a frozen mic `lastVoiceTime` after a mic halt can `stopAll()` the still-healthy sys stream (main.swift:163-170); the WAVWriter destination-collision path churns the carry into a chunk that then gets aborted (consuming error budget per collision) and its `try?` diagnostic rename can orphan the original tmp (WAVWriter.swift:99-104,128-133); `NotchPanelController.arm()` doesn't reset Ask-mode key state on a display-config change, leaving keystrokes going into a collapsed invisible panel (NotchPanelController.swift:104-130); calendar auto-start marks the winning occurrence resolved before the start attempt, so a failed spawn never retries (CalendarAutoStartController.swift:208-212).
