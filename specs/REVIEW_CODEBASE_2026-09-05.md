**Project review — 2026-09-05**

Reviewed working tree at commit `84a5fb8071d0d7ac66f175aee81aa855046a2a50`. Focus: recording lifecycle, recovery/finalization, locks, native audio writer/restart behavior, menu-bar/calendar orchestration, and persistence. Also inspected import, transcription, speaker registry/rename, dashboard escaping, and existing tests. Earlier reviews were used as leads and checked against current source; repaired findings were not carried forward automatically. Application code was not changed.

13 findings: eight P1/high priority, five P2/medium priority. “Reproduced” means an isolated probe exercised the relevant production code; “static” means the finding follows from the inspected control flow without a full runtime reproduction. These are correctness findings, not measured speech-recognition accuracy results.

1. **[P1] Preserve audio when transcription fails.** `src/finalize.ts:L836-L840`, `src/final-pass.ts:L146-L160`: finalization marks the session done and deletes every WAV even when an audible chunk failed and has no fallback text; final-pass errors also become empty strings without failure accounting. **Reproduced:** one audible WAV, failing Whisper executable, no prior entries, and `finalRetranscribe: false` returned zero entries, no warnings, and removed the session directory. Track unresolved failures by chunk; preserve recoverable audio/session state and report failure instead of reaching cleanup. A successful silence result must remain distinguishable from a failed transcription.

2. **[P1] Do not treat missing JSONL metrics as silence during recovery.** `src/finalize.ts:L125-L128`, `src/finalize.ts:L721-L725`: markdown-only entries receive `-Infinity` RMS, then a nonempty `baseEntries` short-circuits the WAV-based fallback. **Reproduced:** two audible, completed chunks in markdown plus only the first JSONL record produced a one-entry transcript and deleted both WAVs with retranscription disabled. Analyze the WAV for each missing metric and merge recovery results per chunk; the presence of one valid JSONL record must not suppress recovery of the rest.

3. **[P1] Quiesce the old pipeline before handing a meeting to the finalizer.** `src/pipeline.ts:L116-L122`, `src/pipeline.ts:L283-L286`, `src/recorder.ts:L507-L523`: `close()` only closes the watcher; queued and in-flight work still processes and writes session/transcript state. The `n` path spawns the finalizer before cleanup and keeps the parent alive for the next meeting, allowing the old pipeline, new recorder, and finalizer to overlap. **Reproduced:** closing a pipeline with one in-flight and one queued chunk still processed both. Stop further dequeueing, await or cancel/persist the active operation, and complete that handoff before spawning the finalizer or next recorder.

4. **[P1] Classify paused capture sessions using process ownership.** `src/recording-state.ts:L18-L24`, `src/recorder.ts:L654-L661`: both active-controller and live-capture checks require `status === "recording"`, although pausing persists `"paused"`. **Reproduced:** a paused session with a live capture PID was classified as stale. After its controller dies, `meet start` misses the orphan and permits another recording; recovery guidance can also target audio still owned by the old capture. Distinguish paused recording from paused finalization and consult matching controller/capture liveness before declaring a session recoverable.

5. **[P1] Publish complete finalizer locks before making them visible.** `src/locks.ts:L148-L150`, `src/locks.ts:L190-L194`, `src/locks.ts:L229-L236`: per-session and global final-pass locks still expose an empty file between exclusive open and metadata write; readers delete unparseable files as stale. **Reproduced interleaving:** open the first lock, call the production reader, acquire a second lock, then finish writing the first descriptor; the reader removed the first owner's lock and the second acquisition succeeded. Publish complete metadata exclusively, as the active-lock path now does, and make reclamation/release conditional on the ownership being removed. Otherwise two finalizers can rewrite/delete the same session concurrently.

6. **[P1] Recover or terminate capture after WAV writer failure.** `native/AudioCapture/Sources/AudioCapture/MicCapture.swift:L190-L203`, `native/AudioCapture/Sources/AudioCapture/SystemAudioCapture.swift:L157-L169`: the writer now enters a closed/failed state on finalization error, but both callers only log and keep calling `appendSamplesIfNeeded`; they never reopen it. Healthy audio callbacks keep updating `lastBufferTime`, so the stall monitor does not repair this. **Reproduced with the production Swift writer:** an injected rename failure was followed by repeated `noOpenChunk` errors. Add explicit storage-error recovery with bounded retry or terminate the stream visibly while preserving failed audio.

7. **[P1] Continue system-tap recovery after a failed restart.** `native/AudioCapture/Sources/AudioCapture/SystemAudioCapture.swift:L203-L214`, `native/AudioCapture/Sources/AudioCapture/SystemAudioCapture.swift:L226-L235`: the restart catch sets `isRunning = false`, while both future recovery entry points require it to be true. A transient device/tap failure during restart therefore disables system capture for the remainder of the meeting. **Static.** Separate capture intent from current tap state, clean partially created resources, and retry with backoff while recording is still requested.

8. **[P1] Include exact back-to-back events when trimming calendar grace.** `native/MenuBar/Sources/MeetMenuBar/CalendarAutoStartController.swift:L207-L211`: filtering future starts with `> candidate.end` discards the common case where the next call starts exactly when this one ends. **Reproduced using the controller's selection expression and production `CalendarMatch.capMinutes`:** five minutes remaining yielded a 13-minute cap instead of five. The extra eight minutes exceed the default five-minute lateness allowance, so the next call never gets its own auto-start. Include equality and add an integration test of successor selection plus cap calculation.

9. **[P2] Display recoverable crashed recordings in `meet status`.** `src/status.ts:L22-L33`, `src/status.ts:L97-L98`: `findRecordingStates()` detects stale recordings, but the formatter consumes only its orphan results; the other buckets omit persisted `status: "recording"`. **Reproduced:** a session with a dead controller and no live capture was absent from status output. Render the stale recording states with their session paths and recovery commands, excluding sessions already displayed in another bucket.

10. **[P2] Lock every registry mutation, including finalization without a medium pass.** `src/finalize.ts:L317-L326`, `src/finalize.ts:L737-L744`: registry updates rely on the global final-pass lock, but that lock is acquired only when retranscription is enabled and its model exists. Diarization still loads/modifies/saves the registry when retranscription is disabled or the model is missing, racing another finalizer or `meet rename`/`meet speakers forget`. **Static.** Put every registry read/modify/write sequence behind the same lock independently of the transcription path; preserve existing ownership when a caller already holds it. Atomic file replacement alone does not prevent lost updates.

11. **[P2] Discard calendar work after auto-record is disabled.** `native/MenuBar/Sources/MeetMenuBar/CalendarAutoStartController.swift:L71-L84`, `native/MenuBar/Sources/MeetMenuBar/CalendarAutoStartController.swift:L151-L171`: disabling the feature invalidates its timer but neither cancels the permission task nor invalidates an already queued fetch. Their continuations can restart polling or call `process(events:now:)`, which does not check `isEnabled`, and start a recording after the toggle is off. **Static.** Recheck enabled state at asynchronous boundaries and immediately before starting; use a generation/cancellation token to reject results from a previous enable cycle.

12. **[P2] Replace finalized transcripts atomically.** `src/assembler.ts:L115-L117`: `rewriteMarkdown()` writes directly to the existing transcript, truncating it before the new content is durable. A disk-write failure or process interruption can replace the readable live transcript with a partial/empty file, even though session recovery may still be possible. **Static.** Use the existing `writeAtomic()` helper for full rewrites, and test that a failed replacement preserves the previous transcript. Incremental append is a separate operation.

13. **[P2] Do not delete the current configuration before replacing it.** `native/MenuBar/Sources/MeetMenuBar/ConfigStore.swift:L25-L30`: Settings saves write a temporary file, remove `config.json`, then move the temporary file into place. A failure/interruption between the last two operations leaves configuration missing; a newly started CLI then uses defaults. **Static.** Replace the destination in one atomic rename using a unique temporary file, and retain the previous configuration if publication fails.

Existing tests require writes under `~/.meet/sessions` and access to macOS system metrics. Those initial failures are not counted as product regressions.
- Six temporary Node probes reproduced findings 1–5 and 9 using compiled production modules, generated PCM WAVs, a failing executable, and synthetic lock/session fixtures. The probes redirected `node:os.homedir()` within the probe process to a temporary directory; no real meeting was finalized or deleted. Finding 3's probe verified work continues after `close()`; the multi-process corruption consequence was established by inspecting the recorder handoff.
- Compiled the production `WAVWriter.swift` and `CalendarMatch.swift` with a temporary Swift harness. It reproduced findings 6 and 8; `CalendarMatch.selfCheck()` also passed. The calendar probe exercised the copied controller selection expression plus the real helper, not EventKit/UI automation.
- Full Core Audio recording, TCC prompts, hardware reconnects, EventKit polling, menu-bar UI, and real Whisper/AudioAnalysis inference were not exercised. Finding 7 and the other findings marked static remain untested against live hardware/process interleavings.
- `native/AudioCapture/Tests/AudioCaptureTests/WAVWriterTests.swift` contains only a placeholder enum; declaring the test target currently supplies no writer regression assertions. Existing calendar self-checks cover equality in the cap helper but not the controller filter that drops that case.

Suggested implementation order: preserve failed/missing chunks (1–2), make recording/finalizer ownership safe (3–5), repair native stream recovery (6–7), then fix calendar scheduling and remaining persistence/status defects (8–13).
