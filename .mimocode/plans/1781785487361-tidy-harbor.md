# Fix Menu Bar App Issues from Code Review `68df7cd`

## Verified Findings

All 4 critical/bug items confirmed by reading the actual code.

### 1. 🔴 CRITICAL — Signal 30 = SIGUSR1 (Extend is broken)

**Root cause:** `RecordingController.swift:77` sends `signal(30)`, but on macOS signal 30 **is** `SIGUSR1`. So `extend()` triggers `togglePause()` instead of `extendCap()`.

**In recorder.ts:** `process.on("SIGUSR3", ...)` at line 516 is dead code — no real signal maps to SIGUSR3 on Darwin.

**Fix:**
- Swift: change `sendSignal(30, ...)` to `sendSignal(SIGWINCH, ...)` (signal 28, safe, unused by Node by default)
- Node: replace `process.on("SIGUSR3", ...)` with `process.on("SIGWINCH", () => this.extendCap())`

**Files:** `native/MenuBar/Sources/MeetMenuBar/RecordingController.swift:77`, `src/recorder.ts:516`

### 2. 🔴 CRITICAL — Hardcoded node path broken on Apple Silicon

**Root cause:** `RecordingController.swift:31` uses `/usr/local/bin/node` (Intel Homebrew). On Apple Silicon it's `/opt/homebrew/bin/node`.

**Fix:** Use `Process()` with `executableURL` resolved via `/usr/bin/env node`, or shell out to find it:
```swift
let whichNode = Process()
whichNode.executableURL = URL(fileURLWithPath: "/usr/bin/which")
whichNode.arguments = ["node"]
let pipe = Pipe()
whichNode.standardOutput = pipe
try? whichNode.run()
whichNode.waitUntilExit()
let nodePath = String(data: pipe.fileHandleForReading.readDataToEndOfFile(), encoding: .utf8)?
    .trimmingCharacters(in: .whitespacesAndNewlines) ?? "/opt/homebrew/bin/node"
proc.executableURL = URL(fileURLWithPath: nodePath)
```

**File:** `native/MenuBar/Sources/MeetMenuBar/RecordingController.swift:31`

### 3. 🟠 BUG — Stop no-op for attached sessions

**Root cause:** `stop()` at line 70 checks `process` (only set when **this** app spawns). `attachToExistingSession()` only sets `attachedPid`, leaving `process == nil`.

**Fix:** Fall back to `attachedPid`:
```swift
func stop() {
    if let proc = process, proc.isRunning {
        sendSignal(SIGINT, to: proc.processIdentifier)
    } else if let pid = attachedPid {
        sendSignal(SIGINT, to: pid)
    }
}
```

**File:** `native/MenuBar/Sources/MeetMenuBar/RecordingController.swift:70-73`

### 4. 🟠 DESIGN — SIGUSR1/SIGUSR2 both toggle (desync risk)

**Root cause:** Both `SIGUSR1` and `SIGUSR2` call `togglePause()`. Swift sends 1 for pause, 2 for resume, but Node toggles on either. If any signal is missed/duplicated, they desync.

**Fix:** Make handlers explicit and idempotent:
```ts
process.on("SIGUSR1", () => {
    if (!this.paused) void this.togglePause();
});
process.on("SIGUSR2", () => {
    if (this.paused) void this.togglePause();
});
```

**File:** `src/recorder.ts:514-515`
