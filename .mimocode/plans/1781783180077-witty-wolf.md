# Plan: Menu Bar App + Raycast Integration

## Problem
Starting a recording requires: open terminal → cd to project → run `node dist/main.js start "Title"`. Too many steps.

## Solution
Two complementary launchers:
1. **Menu bar app** (Swift/SwiftUI) — click-to-record with full controls
2. **Raycast script command** — type title, hit enter, done

---

## Part 1: Signal-based Control for CLI

The recorder currently reads stdin for hotkeys (q/s/n/p/e/a). Add **POSIX signal** support so an external process (the menu bar app) can control recording without a terminal.

### Changes to `src/recorder.ts`

Add signal handlers alongside existing stdin handlers:

| Signal | Action | Current hotkey |
|--------|--------|----------------|
| `SIGUSR1` | Pause recording | `p` |
| `SIGUSR2` | Resume recording | `p` (toggle) |
| `SIGUSR3` | Extend by 15min | `e` |
| `SIGINT` | Stop recording | `q` |

Modify `setupSignalHandlers()` (line ~280) to register `SIGUSR1`/`SIGUSR2`/`SIGUSR3` handlers that call the same methods as the stdin handlers (`doPause`, `doStop`, `doExtend`). The existing `SIGINT` handler already calls `doStop`.

### Changes to `src/cli.ts`

Add `--headless` flag to `meet start`:
- When set: disables stdin raw mode, suppresses interactive prompts (tags, next-meeting)
- Purpose: menu bar app runs the CLI without a terminal

## Part 2: Menu Bar App (Swift/SwiftUI)

New directory: `native/MenuBar/`

### Architecture

```
native/MenuBar/
├── Package.swift
└── Sources/
    └── MeetMenuBar/
        ├── main.swift           — App entry, NSApplication setup
        ├── MenuBarManager.swift — NSStatusItem, menu, popover
        ├── RecordingController.swift — spawns/meets CLI process, sends signals
        └── SessionMonitor.swift — watches ~/.meet/sessions/ for state changes
```

### Behavior

**Idle state** (no recording):
- Menu bar: mic icon (SF Symbol `mic.circle`)
- Click → popover with:
  - Mode toggle: Mic only / Full (mic + system)
  - "Start Recording" button
  - Link to open `~/Meetings` folder

**Recording state**:
- Menu bar: red dot on mic icon (SF Symbol `mic.circle.fill`)
- Click → popover with:
  - Elapsed time (updated every second)
  - Buttons: Pause | Resume | Stop
  - Button: Extend +15m

**Paused state**:
- Menu bar: yellow dot on mic icon
- Same as recording but Resume shown instead of Pause

No title input needed — title auto-generated from timestamp (like existing behavior).

### How it talks to the CLI

1. Spawns: `node /path/to/meet/dist/main.js start "meeting" --headless --mode full`
2. Sends signals via `kill(pid, SIGUSR1)` etc.
3. Monitors state by watching:
   - `~/.meet/sessions/active-recording.lock` — exists = recording active, has `title` and `startedAt`
   - `~/.meet/sessions/meet-{id}/session.json` — full state (status, elapsed, etc.)

### Menu bar extra items
- "Open Meetings Folder" → `open ~/Meetings`
- "Meet Status" → runs `meet status` output
- "Quit" → quits the app (does NOT stop recording)

### Build

```bash
cd native/MenuBar && swift build -c release
# Binary at: native/MenuBar/.build/release/MeetMenuBar
```

### Launch at Login (optional)
Use `SMAppService` (macOS 13+) to register as a login item from the app's menu.

## Part 3: Raycast Integration

Create a Raycast Script Command that can be triggered from Raycast's search bar.

### File: `raycast/meet-start.sh`

```bash
#!/bin/bash
# @raycast.schemaVersion 1
# @raycast.title Start Meeting
# @raycast.mode silent

node ~/www/repos/meet/dist/main.js start "meeting"
```
